stacked passes · native overscroll

Same cascade, the OS does the bounce.

The passes build the deck exactly like the sticky demo — each rises, shows its content, then pins as the next comes up. But the pin is a transform, not position: sticky, so everything stays in flow and the overscroll is the browser's own rubber-band — most faithful on a phone.

01 — index↓

You read each card on the way up.

Every pass is a full screenful and scrolls into view before it pins — so its content is visible, not just a peek.

02 — writing↓

Pinning without sticky.

A scroll-driven transform ramps 1:1 with scroll to hold each pass in its slot — visually identical to sticky, but it stays in normal flow.

03 — work↓

The bounce is the OS's.

Because nothing is pinned to the viewport, pulling past either edge uses the native rubber-band — no spring to tune, no touch handler to fight.

04 — notes↓

Two honest trade-offs.

The native bounce moves everything rigidly (no per-pass elastic spread), and the intro rides along. A little JS measures the pin points, but never touches the bounce.
