stacked passes · sticky + native

Sticky cascade, native bounce.

The deck is built with position: sticky — the browser pins each pass perfectly, so there's nothing to jitter. The overscroll is the OS rubber-band, untouched. The catch: at the bottom only the front pass rides it (the stacked ones are pinned); at the top, all of them do.

01 — index↓

Pinning the browser's way.

Each pass scrolls up showing its content, then sticks at its slot while the next rises — and because it's real sticky, it's rock-still.

02 — writing↓

No counteracting transform.

Nothing is fighting the scroll frame-by-frame, so the stacked passes can't flash between two positions the way the transform version did.

03 — work↓

The bounce is the OS's.

No script, no overscroll-behavior override — pulling past an edge is the native rubber-band, exactly as the platform draws it.

04 — notes↓

The asymmetry.

At the bottom the OS only bounces passes that aren't pinned — so the front pass rubber-bands and the stack holds. The question is whether that reads as natural or wrong.
